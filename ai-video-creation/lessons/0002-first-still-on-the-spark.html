Lesson 0002 · Setup & First Pixels

Your First Still on the Spark

Get ComfyUI running on the DGX Spark and generate one real, commercial-safe image — the first pixels of your pipeline.

Lesson 0001 gave you the map and the one rule: lock consistency on cheap stills before you ever animate. This lesson is where you make the first still. ~15 minutes of reading, then an install you can kick off and walk away from. Your win: one generated image, from a model you can legally ship, running locally on your own hardware — no API, no per-image fee.

1. Why ComfyUI is the whole hub

Every stage from here on — character sheets, keyframe stills, image→video, upscaling — runs through ComfyUI. It's a node graph, not a prompt box: you wire a model → sampler → VAE → save, and every open image/video model (SDXL, FLUX, Qwen-Image, Wan 2.2, HunyuanVideo, LTX) plugs into the same canvas. Learn one tool, run them all. why it's the standard

Mental model. A ComfyUI workflow is a saved graph of nodes. A template is a ready-made workflow that ships with the model. You'll start from a template, run it unchanged, then edit one node — exactly how you'll build every later stage.

2. Install — use NVIDIA's own playbook

The Spark is awkward hardware (ARM64 + Blackwell GB10, sm_121, CUDA 13) and the generic install guides don't account for it. Don't fight that — NVIDIA publishes an official DGX Spark ComfyUI playbook. Use it. official quick-start

The fast path is their one-line setup script (prereq check → venv → PyTorch cu130 → ComfyUI → deps → a ~20 GB starter model), run on the Spark itself:

curl -fsSL "https://raw.githubusercontent.com/NVIDIA/dgx-spark-playbooks/refs/heads/main/nvidia/playbook-comfyui/assets/setup.sh" | bash

Then launch from the same directory (it expects comfyui-env/ and ComfyUI/ there):

curl -fsSL "https://raw.githubusercontent.com/NVIDIA/dgx-spark-playbooks/refs/heads/main/nvidia/playbook-comfyui/assets/launch.sh" | bash
You're on infra you know — treat it that way. Piping a remote curl … | bash is convenient but it's remote code on your box. The playbook also documents the manual Steps 1–7 (venv → pip install torch --index-url …/cu130 → git clone --branch v0.33.2 …/ComfyUI → pip install -r requirements.txt → python main.py --listen 0.0.0.0). Read setup.sh once, then decide. For a long-term brand pipeline, prefer the pinned manual steps or one of the Spark-tuned Docker setups over an unpinned remote script. a Spark-tuned Docker setup

3. Reach the UI

ComfyUI binds to 0.0.0.0:8188. From the Spark itself that's http://localhost:8188; from your laptop it's http://<SPARK_IP>:8188. Confirm it's up before opening a browser:

curl -I http://localhost:8188   # expect: HTTP/1.1 200 OK
macOS gotcha. If the page won't load from your Mac, grant your browser System Settings → Privacy & Security → Local Network access — macOS silently blocks local-network connections until you do.

4. The licensing fork — read before you pick a model

This is exactly the tripwire this course exists to catch. The name "Qwen-Image" now covers two different licenses, and only one is safe for a brand ad:

All five fit the Spark easily — 128 GB dwarfs their size. Fit is never the problem here; the Spark-fit reference tracks every model's fit + speed + license in one place.

The rule, restated. A newer, smaller, faster model is not automatically the one to use. The license card decides, every time. The 7B Qwen-Image-2.1 is tempting (lighter, faster) and wrong for shipping brand work. Verify the weight's license page before you commit to it. the 2.1 licensing wall

5. Your win — generate one still ✍️

Two valid paths. Pick based on what you want to prove today.

Path A — fastest first pixels (NVIDIA's starter)

The playbook ships with Z-Image-Turbo and a one-click template. Run it exactly as the quick-start Step 9 says: Templates → Image → "Z-Image-Turbo: Text to Image" → Run. You get an image in ~30s and you've proven the whole stack works end to end. Use this to de-risk the install — don't ship from it until you've checked its license card for your use.

Path B — your real commercial-safe baseline (recommended to end on)

Load the Qwen-Image (20B, Apache-2.0) native template. ComfyUI will flag any missing weights and name both the Hugging Face source and the models/ subfolder each belongs in — download those, refresh, and Run. official Qwen-Image workflow

For your first prompt, don't chase art. Prove control — generate something that rhymes with your brief from Lesson 0001. A template:

<hero or product from your brief>, <one tone adjective> lighting,
clean studio background, product-photography composition,
sharp focus, 35mm, <aspect ratio from your brief>
What "done" looks like for this lesson: one .png saved by ComfyUI, from a model whose license you've confirmed is commercial-OK, that loosely matches your brief's hero + tone. That's it. Not beautiful — yours, legal, and local.

6. Retrieval check (eyes closed first)

Two models are both called "Qwen-Image." Which can you ship a brand ad with, and how do you know?

The 20B base model (Apache-2.0). Not Qwen-Image-2.1 7B (Qwen Research License, non-commercial). You know by reading the license card on the weight's page — never by the name, size, or recency.

Why install ComfyUI from NVIDIA's playbook rather than a generic guide?

The Spark is ARM64 + Blackwell (sm_121, CUDA 13); generic guides assume x86 + older CUDA and break. The playbook pins the correct PyTorch (cu130), ComfyUI version, and model paths for this exact hardware.

What is a ComfyUI "template," and why start from one?

A ready-made node graph that ships with a model. Starting from a template means the wiring is already correct — you run it, then change one node at a time, which is how every later pipeline stage is built.
