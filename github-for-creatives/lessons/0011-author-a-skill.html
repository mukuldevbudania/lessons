Lesson 0011 · The Mission Advanced

Author Your Own Skill

Package your ad-making know-how as a reusable skill — a SKILL.md plus its prompts and example files — all versioned together in Git. This is what you came for.

Everything so far was building to this. Today you create your own skill repository and fill it with a real, reusable ad-creation skill. About 15 minutes. Your win: a my-skills repo on GitHub containing your first authored skill.

1. What a skill is

A skill is a small, self-contained packet that teaches an AI agent how to do one thing well. At minimum it's a folder containing:

  • SKILL.md — the instructions: what it does, when to use it, step by step.
  • prompts — the actual prompt text the skill relies on.
  • examples / assets — reference files, sample outputs, templates.

You saw this exact shape in mattpocock/skills (Lesson 0005). Now you build your own.

2. Make a skills repo

  1. In GitHub Desktop, Create a new repository named my-skills, with a README. Publish it (private is fine).
  2. Inside, create a folder for your first skill: create-brand-ad/.

3. Write the SKILL.md

Inside create-brand-ad/, make SKILL.md and write your process down the way you'd explain it to an assistant:

# Create Brand Ad

## What this does
Generates a 15-30s cinematic brand ad from a short brief.

## When to use
When I have a product and a mood, and need a shot list + prompts fast.

## Steps
1. Read the brief: product, mood (3 adjectives), target platform.
2. Use `prompts/shot-list.txt` to generate a 4-6 shot plan.
3. For each shot, fill `prompts/veo-shot.txt` with the shot detail.
4. Keep the hero product consistent across every shot.
5. Export per the platform spec in `reference/platforms.md`.

## Files
- `prompts/shot-list.txt` — the shot-planning prompt
- `prompts/veo-shot.txt` — the per-shot generation prompt
- `reference/platforms.md` — aspect ratios & export settings

4. Add the supporting files

  1. Make a prompts/ folder inside create-brand-ad/. Add shot-list.txt and veo-shot.txt with your real, battle-tested prompts.
  2. Make a reference/ folder. Add platforms.md with your export specs (the 9:16 / 16:9 / 1:1 table from your video work).
  3. The structure now looks like this:
my-skills/
├─ README.md
└─ create-brand-ad/
   ├─ SKILL.md
   ├─ prompts/
   │  ├─ shot-list.txt
   │  └─ veo-shot.txt
   └─ reference/
      └─ platforms.md

5. Commit the whole skill as one unit

  1. In GitHub Desktop, all the new files show in Changes.
  2. Commit: Add create-brand-ad skill. Push.
Why versioning a skill matters As you improve the skill — better prompts, new steps — each commit is a labeled version you can roll back to. Your skill evolves with a full history, instead of being a prompt you tweak and lose. That's the whole payoff of this course.
In your world A skill is a reusable template project — like a saved ad template with placeholders. Build it once, reuse it on every client, improve it over time, and never lose a good version.

6. Retrieval check

What are the three parts of a basic skill?

A SKILL.md with instructions, the prompt files it uses, and example or reference assets.

Why keep a skill in Git rather than a loose folder?

Every improvement is a labeled version with full history you can roll back to, so good versions are never lost.

Should the whole skill be committed together?

Yes — SKILL.md, prompts, and references as one commit, so the skill stays a coherent unit.
