Lesson 0012 · The Long Game Advanced

Maintain Your Library

A skills library is a living thing. Here's how to keep yours fresh, updated, and tidy for years — and where to go next.

Final lesson. You have the full toolkit; this is about habits that keep it healthy. About 10 minutes. Your win: a maintenance routine and a clear sense of what "advanced" looks like from here.

1. Pull updates to repos you cloned

Repos like mattpocock/skills keep improving. To get the latest:

  1. Open that repo in GitHub Desktop.
  2. Click Fetch origin — it checks GitHub for new changes.
  3. If there are updates, the button becomes Pull origin. Click it. Your local copy is now current.
In your world Like re-downloading the latest version of a stock-asset pack when the creator ships new content — you pull in their improvements without losing your place.

2. Keep your own repos tidy

  • Commit small and often — one idea per commit, with a clear message. Future-you will thank you.
  • Prune dead files — delete prompts that no longer work; the history still has them if you need them back.
  • Keep READMEs current — when you add a skill, add a line to the README.
  • Use branches for big rewrites (Lesson 0009) so main always works.

3. Recover when something breaks

Git's superpower is that you can go back. If a change breaks a skill:

  • In GitHub Desktop's History tab, find the last good commit.
  • Right-click it → Revert changes in commit to undo a bad change safely (it makes a new commit that reverses it — nothing is destroyed).
  • Stuck? That's what I'm here for — tell me what happened and we'll fix it together.
The mindset shift Because every version is saved, you can experiment without fear. "What if I break it?" stops being scary — you can always walk back to a working commit. That freedom is the real gift of version control.

6. Retrieval check

How do you get the latest version of a repo you cloned?

Click Fetch origin to check for changes, then Pull origin to download them.

How do you safely undo a bad commit?

In History, right-click the commit and Revert changes — it adds a new commit reversing it, destroying nothing.
