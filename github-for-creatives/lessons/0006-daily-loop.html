Lesson 0006 · Rhythm Intermediate

The Daily Loop

Edit → commit → push, over and over. This small rhythm is 90% of using GitHub for the rest of your life.

Back to your own my-prompts repo. Today you make the loop automatic. About 10 minutes. Your win: you can confidently change a file and get it safely to the cloud without thinking twice — and know what pull is for.

1. Make a change

  1. Open my-prompts in GitHub Desktop, click Show in Explorer.
  2. Edit your veo-cinematic-ad.txt — tweak the prompt, add a line. Save.
  3. Add a brand-new file too, say product-closeup.txt, with another prompt. Save.

2. Review what changed — the superpower

Back in GitHub Desktop, the Changes panel lists both files. Click each one: on the right, GitHub Desktop shows you exactly what changed — new lines in green, removed lines in red. Nothing is a mystery.

In your world This is a before/after diff — like comparing two versions of an edit side by side to see precisely what moved. You never have to guess what a change did.

3. Commit, then push

  1. Write a clear Summary: Tweak cinematic prompt, add product closeup.
  2. Click Commit to main.
  3. Click Push origin at the top. Your changes are now on GitHub.com.
The loop, every time: edit → review the diff → Commit to main → Push origin.

4. When do you pull?

Pull brings down changes that exist on GitHub.com but not on your PC yet. You'll need it when:

  • You edited a file directly on the github.com website.
  • You work on a second computer and pushed from there.
  • (Later) a skills repo you cloned got updated and you want the new version — covered in Lesson 0012.

The button is Pull origin. If there's nothing to pull, it simply says you're up to date.

Good habit When in doubt, pull before you start editing. It makes sure your local copy matches the cloud before you add to it — avoids confusion down the line.

5. Writing good commit messages

A commit message is a note to your future self. Make it say what changed, briefly:

WeakGood
"update""Add product-closeup prompt"
"stuff""Fix lighting cue in cinematic ad"
"asdf""Remove unused draft prompt"
Primary source Committing and reviewing changes in GitHub Desktop.

6. Retrieval check

What are the three steps of the everyday loop?

Edit the files, commit a labeled version, then push it up to GitHub.com.

Where do you see exactly what a change did?

In the Changes panel — clicking a file shows a diff with added lines green, removed lines red.

Name one time you'd need to pull.

After editing on the website, pushing from another computer, or updating a cloned repo.
