Lesson 0009 · Safe Experiments Advanced

Branches

A branch is a safe parallel copy where you can try bold changes without touching the version that works.

Until now you've worked on one line called main. Branches let you experiment fearlessly. About 10 minutes. Your win: you can spin off a branch, try something, and either keep it or throw it away — with main untouched the whole time.

1. The idea

Your main branch is the "real," working version of the repo. A branch is a copy that splits off from main so you can make changes in isolation. If the experiment works, you fold it back into main. If it flops, you delete the branch and main never knew.

In your world Like duplicating a sequence before a risky re-edit. You hack on the copy; the original timeline stays safe. If the new cut is better, it becomes the master; if not, you delete the duplicate.

2. Create and switch to a branch

  1. In GitHub Desktop, click the Current branch dropdown at the top (it says main).
  2. Click New branch. Name it experiment-ad-generator. Click Create branch.
  3. You're now on that branch — the dropdown shows its name. Every commit you make now lands here, not on main.

3. Experiment freely

  1. Add or heavily rewrite a prompt file — try a wild new ad-generator idea.
  2. Commit it as usual: Try new ad-generator approach.
  3. Flip the Current branch dropdown back to main and look at the folder — your experimental change isn't there. It's safely on the other branch. Switch back to continue.

4. Keep it, or bin it

If the experiment is good — merge it into main:

  1. Switch to main (Current branch dropdown).
  2. Branch → Merge into current branch, pick experiment-ad-generator. Your work is now part of main. Push.

If it flopped — just delete the branch (Branch → Delete) while on main. Gone, no harm done.

Scope note On teams, branches usually go through "Pull Requests" for review. We're deliberately skipping PRs — for solo creative work, create → experiment → merge or delete is all you need. You can learn PRs later if you ever collaborate.
Primary source Managing branches in GitHub Desktop.

5. Retrieval check

What is a branch, in one line?

A parallel copy of the repo where you can change things without affecting the main version.

If an experiment on a branch fails, what happens to main?

Nothing — main is untouched; you simply delete the branch and move on.

How do you keep a good experiment?

Switch to main and merge the branch into it, then push.
