Lesson 0007 · Structure Intermediate

Organizing a Repo

Folders and a README turn a pile of files into a library you (and your agent) can actually navigate.

A repo with 50 loose .txt files is a junk drawer. Today you give my-prompts a shape that scales. About 10 minutes. Your win: a tidy folder structure and a README that explains the repo at a glance.

1. Group files into folders

Decide a few top-level buckets that match how you think about your work. For a videographer, something like:

my-prompts/
├─ README.md
├─ ads/
│   ├─ cinematic-ad.txt
│   └─ product-closeup.txt
├─ ai-video/
│   ├─ veo-recipes.txt
│   └─ runway-shots.txt
└─ reusable/
    └─ brand-voice.txt
  1. In Explorer, create folders ads, ai-video, reusable inside the repo.
  2. Drag your existing prompt files into the right folders.
  3. Back in GitHub Desktop, the Changes panel shows the files moving. Commit: Organize prompts into folders, then push.
In your world Exactly like bins in your editing project — Footage, Audio, Graphics. Folders in a repo are bins. Future-you finds things in seconds instead of scrolling.

2. Write a README

A README.md is the welcome note that shows on the repo's front page on GitHub.com. It's a plain text file written in Markdown (simple formatting). It should answer: what is this, and how do I use it?

  1. Open the README.md that was created with the repo.
  2. Replace its contents with something like the example below.
  3. Commit Write README and push. Refresh the repo on github.com — the README now renders beautifully on the front page.
# My Prompts

My personal library of prompts for ads and AI video.

## Folders
- `ads/` — brand ad prompts
- `ai-video/` — AI video generation recipes
- `reusable/` — brand voice and snippets I reuse everywhere

## How I use this
Copy a prompt, adapt the bracketed bits, paste into the tool.

Why this helps you specifically When you later build skills, a good README + folder layout is what lets an AI agent (and other people) understand your library. Tidy structure isn't neatness for its own sake — it's what makes the library usable.

4. Retrieval check

What is a README and where does it show?

A Markdown welcome file that renders on the repo's front page on GitHub.com.

In Markdown, how do you write a top heading?

Put a single hash and a space before the text, like "# Title" on its own line.

Why organize prompts into folders?

So the library scales and stays findable for you, other people, and an AI agent.
