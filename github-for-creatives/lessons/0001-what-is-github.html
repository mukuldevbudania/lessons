What GitHub Actually Is

Before a single click: the one idea that makes everything else make sense — a repository is a project folder that remembers every version of itself.

You've never opened a terminal, and for this whole first stretch you won't need to. Today is pure concept — about 5 minutes, no software, no typing. Your win: you'll be able to explain, in your own words, what GitHub is for and why it's worth your time.

1. The problem GitHub solves

You already know this problem — you've lived it in editing. You have ad_final.prproj, then ad_final_v2.prproj, then ad_final_REALLY_final.prproj, then ad_final_use_this_one.prproj. Which one is right? What changed between them? If you overwrite the good one, is it gone forever?

GitHub (and the tool underneath it, Git) exists to end that mess. Instead of a pile of renamed copies, you keep one project that quietly remembers every version — labeled, dated, and recoverable.

In your world Think of it like a timeline with unlimited undo that never forgets — but for a whole project folder, not just one edit. Every time you hit "save a version," GitHub snapshots the entire folder and keeps that snapshot forever. You can scrub back to any point.

2. The three words to anchor on

  • Git — the engine. The thing that does the version-remembering, running on your own PC. You rarely touch it directly.
  • GitHub — the website (github.com) where your projects live in the cloud, backed up and shareable.
  • Repository (or "repo") — one project. A folder full of your files plus its entire version history. This is the single most important word in the course.
In your world A repository = a project folder, the way a Premiere project is a folder of clips, graphics, and a timeline. The difference: a repo also carries its own full history and can sync itself to the cloud.

3. Why this matters for your mission

Everything you want to do sits on top of this one idea:

  • Save your prompts, ad templates, and AI-video recipes so a good one is never lost or overwritten.
  • Pull in other people's skills from GitHub to use on your own machine (that's "cloning" — Lesson 0005).
  • Eventually build your own skills library — prompts and files, versioned together, growing over time.

Each of those is just a repository. Learn the repo, and the rest is detail.

Primary source Read GitHub's own 2-minute explainer: About Git — GitHub Docs. It's the most trustworthy, plainest statement of the idea.

4. Retrieval check (answer out loud first)

In one sentence, what is a repository?

A single project — a folder of files together with its entire version history.

What's the difference between Git and GitHub?

Git is the version-remembering engine on your PC; GitHub is the cloud website where repositories are stored and shared.

Name one thing from your mission that is "just a repository."

Your prompts library, your ad templates, a cloned skills repo, or your own skills library — each is one repository.
