Lesson 0004 · First Win Beginner

Your First Repo

Create a repository, save a real prompt into it, and watch it appear on GitHub.com. This is the moment it clicks.

Today you do all four words for real. About 12 minutes. Your win: a repository called my-prompts that lives both on your PC and on GitHub.com, with your first prompt saved inside it — committed and pushed.

1. Create the repository

  1. In GitHub Desktop, click Create a new repository (or File → New repository).
  2. Name it my-prompts. For Local path, pick somewhere easy like Documents — this is the folder on your PC where the files will live.
  3. Tick Initialize this repository with a README. Leave the other options alone. Click Create repository.
What just happened GitHub Desktop made a real folder at Documents\my-prompts on your PC and turned it into a repository (it's now tracking versions). It also made a first commit for you — the README. It is not on GitHub.com yet — that's the push, in step 4.

2. Add a prompt file

  1. Open the repo folder: in GitHub Desktop click Show in Explorer (under Repository menu, or the "Open in Explorer" button).
  2. In that folder, right-click → New → Text Document. Name it veo-cinematic-ad.txt. (Make sure it ends in .txt, not .txt.txt.)
  3. Open it and paste one of your real prompts — e.g. your go-to cinematic ad prompt. Save and close the file.
In your world You just dropped an asset into the project folder. GitHub Desktop is already watching that folder, the way your editor watches a project bin — it noticed the new file instantly.

3. Commit it — save a labeled version

  1. Switch back to GitHub Desktop. On the left you'll see veo-cinematic-ad.txt listed under Changes, with a green + — that means "new file." Click it to see the content on the right.
  2. At the bottom-left, type a Summary: Add cinematic ad prompt. This is your commit message — the label.
  3. Click the big Commit to main button.
What just happened You made a commit — a labeled snapshot saved locally. The Changes list is now empty because everything is saved. Still local-only.

4. Push it — send it to the cloud

  1. At the top, click Publish repository (the first push of a brand-new repo is called "publish").
  2. A box appears. Keep the name my-prompts. Important: untick Keep this code private only if you want it public — for your own prompts, leave it private (ticked). Click Publish repository.
  3. Wait a few seconds. Done — it's on GitHub.com.
The full loop you just did: Create repository → add a file → Commit to main → Publish / Push → it's on GitHub.com.

5. See it on the website

In GitHub Desktop, click Repository → View on GitHub (or just open github.com and find my-prompts under your repositories). You'll see your veo-cinematic-ad.txt sitting there, with your commit message. That file is now safe, versioned, and in the cloud. 🎉

Private vs public A private repo is visible only to you — right for personal prompt libraries. A public repo is visible to everyone — right for skills you want to share later. You can change this any time in the repo's settings on GitHub.com.
Primary source GitHub's own version of this walkthrough: Creating your first repository using GitHub Desktop.

6. Retrieval check

After "Commit to main," is your file on GitHub.com yet?

No. Commit saves it locally; it reaches GitHub.com only after you publish or push.

What is the commit Summary for?

It is the label describing what this snapshot changed, so your history is readable later.

Should a personal prompt library be private or public?

Private — visible only to you. Make a repo public only when you want to share it widely.

👩‍🏫 You just did the entire core loop — that's the Beginner milestone. You can now save and back up any creative file forever.
