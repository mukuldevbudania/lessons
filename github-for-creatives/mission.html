Why this course exists

Mission

The one outcome every lesson is aimed at — so no lesson drifts into GitHub trivia you'll never use.

Learner

My brother — a videographer. Deeply creative and visual, but has never used a terminal or command line. Works on a Windows PC. Has a GitHub account already.

Why he wants this

He wants to treat his creative work the way engineers treat code — kept safe, versioned, and reusable — without the fear of losing a good prompt or overwriting a working ad template.

Concretely, he wants to be able to:

  1. Pull in ("clone") skills repos from GitHub so he can use other people's AI/agent skills on his own machine.
  2. Create his own repositories to save his prompts, ad templates, and AI-video recipes.
  3. Eventually, author his own skills — for creating ads and AI videos — and keep each skill's prompts and files versioned together in Git.
The north star His own, well-organized, version-controlled skills library on GitHub — prompts, templates, and files all safe and reusable, built up over time.

Out of scope (for now)

  • GitHub Issues
  • Pull Requests
  • CI / Actions / workflows
  • Collaboration / review flows

We stay on the solo-creator path: install → understand → clone → save → organize → author.

Teaching stance

  • GitHub Desktop first. The GUI app is the primary tool through Beginner and Intermediate. The terminal is introduced only at the Advanced stage, once the mental model is solid.
  • Mental model before mechanics, grounded in videographer analogies.
  • Short, single-win lessons. One tangible win each.
